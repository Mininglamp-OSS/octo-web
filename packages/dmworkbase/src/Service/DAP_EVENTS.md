# DAP octo-web-native event table

Single-source convergence artifact for PR #1407 (DAP UI telemetry integration).
Review **this table**, not the diff: it enumerates every wired octo-web-native event,
the channel it fires on, the exact success condition, the negative/failure edge it must
NOT fire on, its reset/dedup rule, and the test that pins it.

**Channels** (each event lives in exactly one — cross-channel duplication is a bug the
`channelUniqueness` test guards against):
- `fetch` — first-party same-origin 2xx on a path → event (FetchRules.ts). Path selects the name, never stored.
- `body` — request-body top-level key/value → event (BodyRules.ts). `equals` discriminators whitelist the value; `hasKeys` is presence-only.
- `track(testid)` — global capture-phase click/keyboard delegation on `data-testid` (TrackRules.ts).
- `data-track` — DOM attribute on the element; delegation covers mouse + keyboard; `data-track-ignore` subtrees suppress.
- `imperative` — explicit `Dap.shared.track(event, props)` at the confirmed-action site.
- `helper` — gated helper (trackMessage.ts sendack-consumed intents; summaryApi.ts envelope-code gate).

**Privacy**: props are `{}` except an opaque `object_id` join key on a few events
(channel/group id, account uid) — internal random ids, never content/keyword/PII.
See issue #1406 (privacy constraint amended round-6 to permit opaque `object_id`).

**`channel_id` 归一约定 (#1452 R10 P2-2)**: 本 PR 新增/收口的所有命令式事件统一发 **bare
channel_id** —— 即经 `stripSpacePrefix()` 去掉 Space 部署下的 `s<32hex>_` 前缀,取裸 group_no /
uid。覆盖 `conversation_muted` / `conversation_pinned` / `channel_search_query` /
`group_bot_free_mention_toggled` / `subchannel_created` / `subchannel_opened`(两入口)。
目的是让这些事件在 Space 部署下能按同一 `channel_id` 跨事件 join(否则同一频道在带前缀 / 不带
前缀两种形态间对不上)。注意这**不是**与后端某接口对齐:`_search_` / group setting 等接口各自的
strip 口径并不一致(`SearchService` 发 raw、`ChannelSettingService` 仅对 Person strip),故不能
以「跟接口一致」为由——统一到 bare 是为数仓 join。**唯一例外**:既有已上线的 DOM 事件
`channel_opened`(`data-object-id`)保留 **raw** channelID,不改其口径以免二次改变已发布指标的
序列(见该行);跨事件 join 到 `channel_opened` 需在查询侧自行 strip。

**Infra events** (not user intents): `app_launched` (once, post-login — deferred so
anonymous login-page visitors get no device_id / tokenless POST), `http_request`,
`page_view`, `page_leave`.

**Test coverage note**: events marked "—" have no *dedicated* positive-emission test.
Many are still covered indirectly — the `fetch` events by the generic FETCH_RULES
"every rule is hit by its own concretized path" invariant, and several imperative UI-only
events by the negative `channelUniqueness` / FetchRules guards asserting they must NOT
appear in the path channel. Genuinely unpinned positive fires are the honest gap this
table surfaces for follow-up.

Total rows in this table: **145** (`grep -c '^| \`'` — includes the 4 infra rows and a
handful of removed-rule tombstones kept as ~~struck~~ history; the earlier "132 wired"
figure was stale and is dropped to avoid a count that contradicts the table). Out of
scope: octo-docs, octo-fleet.
